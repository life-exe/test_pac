# Подготовка и доставка Pull Request

## Порядок действий

1. Проверить текущую ветку (`git branch --show-current`) и чистоту рабочего дерева (`git status --short`). Если текущая ветка — `master`, предложить сначала создать рабочую ветку (`git checkout -b <branch>`). Если есть незакоммиченные изменения — предложить сначала оформить коммит через `/smart-commit`.
2. Собрать все коммиты и изменения ветки относительно `master`: выполнить `git log master..HEAD` и `git diff master...HEAD`.
3. Определить итоговый уровень риска Pull Request (`Tier: Low`, `Tier: Standard` или `Tier: High`) по правилу старшего уровня: если в ветке есть коммиты разных уровней, всему PR присваивается максимальный из них.
4. Составить заголовок и описание Pull Request для ревьюера:
  - заголовок `--title "<type>(<scope>): <summary>"` (при слиянии через `--squash` он станет заголовком коммита в `master`);
  - тело `--body` с кратким описанием изменений и их мотивации (*Why*), сводной секцией `Testing:` и футером `Tier: <Low | Standard | High>`.
5. Вывести готовые команды доставки для разработчика:
  - `git push -u origin <branch>`
  - `gh pr create --title "..." --body "..."`
  - `gh pr checks --watch`
  - `gh pr merge --squash --delete-branch`
6. **Ограничение:** никогда не выполнять `git push`, `gh pr create` или `gh pr merge` самостоятельно — только вывести готовые команды для разработчика.
