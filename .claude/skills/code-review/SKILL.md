# Предкоммитное код-ревью (Maker & Checker)

## Порядок действий

1. **Прочитать `AGENTS.md`.**
   Загрузить актуальные архитектурные правила и стандарты кодирования проекта.
2. **Собрать изменения.**
   Выполнить `git status --short`, `git diff` и `git diff --staged` (если изменения уже закоммичены в рабочей ветке — `git diff master...HEAD`).
3. **Провести независимую проверку по чеклисту.**
   Если среда поддерживает запуск подагентов (subagents), поручить проверку диффа новому подагенту в чистом контексте, передав ему только `git diff` и правила `AGENTS.md`. Проверить каждый пункт:
   - **Архитектура:** предметная логика находится в `AppLib`, `main.cpp` остаётся тонким.
   - **Стиль C++23:** инициализация через `{}`, строчный суффикс `f` у чисел `float`, `const` и `std::string_view`, типы `PascalCase`, функции `camelCase` в пространстве имён `LifeExe`.
   - **Комментарии и Doxygen:** комментарии в C++, CMake и Python написаны только на английском языке и отвечают на вопрос *почему*; публичные объявления в `.h` снабжены Doxygen-комментариями (`///`, `///<`).
   - **Тесты и чистота репозитория:** новые ветки логики покрыты тестами в `Tests/`, в диффе нет отладочного вывода и лишних файлов.
4. **Запустить быстрые проверки.**
   Если в диффе затронуты файлы C++ или CMake, выполнить:
   - `python automation/format_files.py --check`
   - `python automation/run_tests.py`
5. **Сформировать отчёт.**
   Вывести замечания с точными ссылками `файл:строка` по трём уровням:
   - `[CRITICAL]` — блокеры слияния (нарушение архитектуры, падение тестов, русские комментарии в коде, ошибки управления памятью);
   - `[WARNING]` — отступления от стандартов `AGENTS.md`, отсутствие теста или Doxygen-комментария;
   - `[NIT]` — мелкие рекомендации по читаемости.
   В конце вывести итоговый вердикт: `Ready for PR` (если нет `CRITICAL` и `WARNING`) или `Needs fixes`.

## Ограничения

- Скилл работает только в режиме проверки (read-only): не редактировать файлы и не создавать коммиты без отдельного поручения пользователя.
- Не выдумывать искусственные замечания: если в категории пусто, написать `Нет замечаний`.
