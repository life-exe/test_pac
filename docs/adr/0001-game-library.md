# 0001. Выбор графической библиотеки для игрового каркаса

## Статус
Принято (Accepted)

## Контекст (Context)
Для разработки 2D-игры в рамках инженерного курса по C++ необходима легковесная графическая библиотека, обеспечивающая создание окна, обработку пользовательского ввода, отрисовку 2D-примитивов/спрайтов и воспроизведение звука.

В спринтах `05-raylib-dependency`, `06-sdl-dependency` и `07-sfml-dependency` были созданы три исследовательские ветки (Spike Solutions) для оценки кандидатов:
1. **Raylib 5.5** — компактная библиотека на C с минимумом бойлерплейта и батарейками «все в одном».
2. **SDL 3.2** — низкоуровневый промышленный C-стандарт для работы с мультимедиа.
3. **SFML 3.0** — объектно-ориентированная мультимедийная библиотека на C++17.

Архитектура проекта строго разделена на независимое ядро (`GameCore`), адаптер представления (`GamePresentation`) и точку входа (`GameApp`). Требовалось выбрать библиотеку, наилучшим образом подходящую для учебных целей.

## Решение (Decision)
Мы выбираем **Raylib** в качестве основной графической библиотеки для нашего проекта.

Ветка `spike/raylib` принимается в качестве эталонной реализации слоя представления и мержится в ветку `master`.

## Последствия (Consequences)
**Положительные:**
- **Быстрый старт и прозрачный код**: инициализация окна и базовый рендеринг занимают минимум строк без сложного шаблонного кода.
- **Все необходимое из коробки**: 2D-рендеринг, шрифты и аудиосистема встроены в один Conan-пакет `raylib/5.5.0` без транзитивных зависимостей.
- **Быстрая сборка в CI**: минимальное количество компилируемых сторонних исходников по сравнению с SDL и SFML.
- **Обучение C++ обёрткам**: процедурный API Raylib требует написания чистых RAII-обёрток в слое `Presentation`, что формирует правильные инженерные навыки без риска протекания графических типов в ядро `GameCore`.

**Отрицательные / Компромиссы:**
- Процедурный Си-интерфейс без пространств имён требует осторожности при совместном включении системных заголовков Windows (проблема решена через Precompiled Headers в `GamePresentation`).
- Для продвинутых эффектов (кастомные шейдеры, сложные конвейеры рендеринга) возможности Raylib уступают гибкости SDL.

## Рассмотренные альтернативы (Alternatives Considered)
- **SDL 3**: мощный отраслевой стандарт, однако для полноценной игры требует подключения 3 дополнительных пакетов (`SDL_image`, `SDL_ttf`, `SDL_mixer`) и написания обширного инфраструктурного кода. Рекомендуется для коммерческих мультиплатформенных проектов и нестандартного аппаратного окружения.
- **SFML 3**: элегантный объектно-ориентированный C++ API, однако пакет тянет за собой громоздкие зависимости (FreeType, OpenAL), заметно увеличивая время холодной сборки в CI.
